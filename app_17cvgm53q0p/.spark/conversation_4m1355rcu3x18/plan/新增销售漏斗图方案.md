## 目标与成功标准

在数据仪表盘（/）和客户页「销售进度」页签各增加一张「销售漏斗」图表卡片，按销售阶段（线索→初步接触→需求确认→方案报价→谈判中→已成交，不含已流失）展示客户数漏斗。成功标准：两处漏斗数字与看板各列计数一致；拖拽看板改变阶段后漏斗实时同步；加载/失败/空态齐备。

## 关键实现文件

- 新建 `client/src/pages/Dashboard/SalesFunnelChart.tsx` — 漏斗图卡片组件（仿 StatusPieChart.tsx 范式：Card + ChartState + ReactECharts）
- `client/src/pages/Dashboard/chart-palette.ts` — 新增 `FUNNEL_STAGE_COLORS`（6 阶段色阶：primaryLight→primary 渐变系，已成交用 success）
- `client/src/pages/Dashboard/DashboardPage.tsx` — 新增 funnelQuery + 第三行渲染漏斗卡片
- `client/src/pages/Customers/CustomersPage.tsx:153-154` — kanban 视图改为漏斗卡片 + 看板上下排列
- 后端无改动（复用 `GET /api/customers`，前端按 `crm.salesStage` 计数，与看板同源同口径）

## 实现方案

### 数据口径

- 数据源：`fetchCustomers()`（client/src/api/customer.ts:12，返回 `CustomerListResponse { items, total }`），不新增后端接口
- 计数：`items` 按 `customer.crm.salesStage` 分组计数；阶段顺序取 `SALES_STAGES`（shared/customer.ts:22）过滤掉「已流失」后的 6 个阶段，缺失阶段补 0
- 客户页漏斗直接用页面已有 `items`（受搜索关键词过滤，与看板同步）；仪表盘新增一次 `useDashboardQuery<CustomerListResponse>(fetchCustomers)` 查询

### SalesFunnelChart 组件

- Props：`{ customers: Customer[]; loading: boolean; error?: boolean; onRetry?: () => void }`（与 StatusPieChart.tsx:9-14 同构）
- useMemo 内聚合阶段计数；ECharts option：`series[0] = { type: 'funnel', sort: 'none'（保持阶段顺序，禁止默认降序）, minSize: '24%', left: 'center', width: '70%', label: { show: true, position: 'inside', formatter: '{b} {c} 客' }, data: 各阶段 { name, value, itemStyle: { color: FUNNEL_STAGE_COLORS[stage] } } }`，`tooltip: { trigger: 'item' }`
- 外层 Card + CardHeader（CardTitle「销售漏斗」）+ ChartState（empty 条件：总客户数为 0，emptyText「暂无客户阶段数据」），`<ReactECharts option theme="ud" className="h-[300px] w-full" />`（同 StatusPieChart.tsx:79-83）
- 组件放 `client/src/pages/Dashboard/` 目录，复用同目录 ChartState 与 chart-palette；客户页经 `@client/src/pages/Dashboard/SalesFunnelChart` 跨页引用（仅此一处跨页 import，避免重复实现 ChartState）

### 页面接入

- DashboardPage：`funnelQuery = useDashboardQuery<CustomerListResponse>(fetchCustomers)`；在现有两个图表 grid 之后新增一行 `<SalesFunnelChart customers={funnelQuery.data?.items ?? []} loading error onRetry={funnelQuery.reload} />`（独立整行卡片）
- CustomersPage：`view === 'kanban'` 分支由单 `<CustomerKanban>` 改为 `<div className="space-y-6"><SalesFunnelChart customers={items} loading={loading} onRetry={() => void loadCustomers()} /><CustomerKanban ... /></div>`；看板拖拽 `handleStageChange` 已乐观更新 items（CustomersPage.tsx:88-94），漏斗自动同步

## 影响范围与风险

- 仪表盘新增一次 `/api/customers` 请求（bitable 读取）；失败时该卡片独立显示重试态，不影响其他卡片（useDashboardQuery 各查询隔离）
- 漏斗为「当前阶段分布」非累计转化，数值不一定单调递减——用 `sort:'none'` 按阶段顺序展示，属预期设计
- 客户页漏斗随搜索关键词过滤，与看板列计数保持一致
- 不改后端、不改 shared 类型、不动看板逻辑

## 验收标准

- 仪表盘出现「销售漏斗」卡片：6 阶段按序展示、颜色与调色板一致、inside 标签显示「阶段名 数量」；loading 骨架/失败重试/空态正常
- 漏斗各阶段数量 = 客户页看板对应列头计数（已流失不计入）
- 客户页「销售进度」页签：漏斗卡片在看板上方；拖拽客户卡到另一阶段后漏斗数量即时变化
- 搜索关键词后客户页漏斗与看板同步过滤
- 无横向滚动、无 TS/ESLint 报错
