# 需求分析

## 用户故事

1. 修复登录后闪退问题
  - 1.1 用户登录成功后能稳定停留在工作台首页，不被自动弹回登录页
  - 1.2 登录态校验失败时给出「登录已过期，请重新登录」等明确提示，而不是静默闪退
  - 1.3 仅在确属未授权（401）时才清除登录态并跳转登录页，权限不足等其他错误正常提示不跳转
  - 1.4 刷新页面或重新打开应用后，有效登录态保持，直接进入工作台

2. 支持手机号登录
  - 2.1 用户在登录页输入已绑定的手机号和密码，能成功登录并进入工作台
  - 2.2 原用户名 + 密码登录方式仍然可用
  - 2.3 手机号未登记或密码错误时，提示「用户名/手机号或密码错误」
  - 2.4 账号被禁用时提示「账号已被禁用，请联系管理员」

3. 支持飞书登录
  - 3.1 用户在登录页点击「飞书登录」，识别到已绑定的系统账号后直接进入工作台
  - 3.2 飞书身份未绑定系统账号时，引导输入一次用户名和密码完成绑定并自动登录
  - 3.3 绑定成功后再次使用飞书登录，无需再输入账号密码
  - 3.4 一个飞书账号只能绑定一个系统账号，重复绑定给出明确提示
  - 3.5 管理员可在用户管理中看到各账号的飞书绑定状态

## 业务模型

### API 设计

#### 登录页相关
**页面路径**: /login
**功能全景**：
| 功能 | 实现方式 | 说明 |
|------|----------|------|
| 用户名或手机号 + 密码登录 | API | POST /api/auth/login（改造） |
| 飞书身份识别并登录 | API | POST /api/auth/feishu-login（新增，公开） |
| 飞书身份绑定系统账号并登录 | API | POST /api/auth/feishu-bind（新增，公开） |
| 登录态会话校验 | API | GET /api/auth/me（现有，前端消费方式修复） |

**所需 API**:
```typescript
// 账号密码登录改造：服务端按 username 或 phone 任一匹配，命中后校验密码与启用状态
// [领域模型: AppUser] [对应页面功能: 账号/手机号登录]
POST /api/auth/login
Request: { username: string; password: string }  // username 字段兼容承载手机号
Response: { token: string; user: AppUserWithRole; permissions: string[] }

// 飞书登录：从请求上下文读取平台用户身份（req.userContext.userId），
// 按 app_user.feishu_user_id 匹配；命中且启用则签发 JWT；
// 未命中返回 409 { code: 'FEISHU_UNBOUND' }；非飞书环境（无身份）返回 401
// [领域模型: AppUser] [对应页面功能: 飞书登录]
POST /api/auth/feishu-login
Request: {}
Response: { token: string; user: AppUserWithRole; permissions: string[] }

// 飞书绑定：先校验请求上下文存在平台身份，再按用户名/手机号 + 密码校验系统账号，
// 校验通过后把当前飞书身份写入该账号的 feishu_user_id 并签发 JWT；
// 该飞书身份或该账号已被其他账号绑定时返回 409
// [领域模型: AppUser] [对应页面功能: 飞书未绑定时绑定并登录]
POST /api/auth/feishu-bind
Request: { username: string; password: string }
Response: { token: string; user: AppUserWithRole; permissions: string[] }
```


## 关键技术说明

### 闪退问题排查方向（按现有代码定位的疑似根因）
1. 401 响应拦截器使用 `window.location.replace` 整页硬跳转，与 React Router 的 `navigate` 时序竞争，登录成功后首个 401（含会话校验、待办接口等）会触发整页闪回登录页
2. 登录成功后 `token` 状态变更会再次触发 `GET /api/auth/me` 重复校验，校验失败仅打日志不清理状态，造成「有 token 无用户」的不一致中间态
3. 权限不足返回 403 与未授权 401 未区分处理，403 也可能被误清登录态

修复原则：401 清理登录态改为 AuthProvider 状态驱动（清除 token + 由路由守卫自然回到登录页）并给出提示；拦截器仅保留无 token 场景兜底；`/api/auth/login`、`/api/auth/feishu-login`、`/api/auth/feishu-bind` 三个登录接口排除在 401 跳转逻辑之外；会话校验失败区分「过期/无效」与「网络错误」。

### 飞书登录能力来源（平台内置，不重复造轮子）
- 飞书身份获取复用平台能力：服务端直接读取网关注入的 `req.userContext.userId`（妙搭用户 ID，字符串透传），无需自建 OAuth
- 前端飞书身份是否可用以服务端 `/api/auth/feishu-login` 的返回为准（非飞书环境返回 401 时隐藏/置灰飞书登录入口并提示用账号密码登录）
- 沙箱预览态平台账号接口可能不可用，属已知限制，以发布态为准；不为此新增兜底逻辑
