# 需求分析
## 用户故事
1. 删除系统账号，管理员可在账号列表删除不再使用的账号
  - 1.1 账号列表操作栏有「删除」入口，点击后弹出二次确认弹窗并展示待删除账号名称
  - 1.2 确认删除后账号从列表移除，并显示成功提示
  - 1.3 当前登录账号不展示删除入口；服务端收到删除自身请求时拒绝并返回错误提示
  - 1.4 内置管理员账号（admin）删除时被拒绝，页面展示后端返回的错误信息
  - 1.5 取消确认弹窗时不做任何变更，列表保持原状

## 页面列表
### 用户管理页（现有页面扩展）
1. 操作栏在「编辑」「禁用」旁新增「删除」按钮，仅对非当前登录账号行展示
2. 点击删除触发二次确认弹窗，展示待删除账号名称，确认后调用删除接口
3. 删除成功 toast 提示并刷新账号列表；失败展示后端错误文案（如内置管理员保护）
4. 列表加载/空状态沿用现有页面设计，删除行在刷新后自然消失

# 技术方案
## 开发元信息
- 开发模式: 全栈应用
- 涉及层级: 服务端, 前端
- 复用说明: 复用已有 `DELETE /api/auth/users/:id` 接口（`user:manage` 权限守卫、内置管理员保护、404 用户不存在均已实现），本次仅补服务端自身保护与前端入口；不涉及数据库变更

## 业务模型
### API 设计
#### 用户管理页 相关
**页面路径**: 用户管理页（现有路由）
**功能全景**：
| 功能 | 实现方式 | 说明 |
|------|----------|------|
| 账号列表/新增/编辑/启禁用 | API | 现有接口，保持不变 |
| 删除账号 | API | DELETE /api/auth/users/:id（已存在，本次服务端新增「禁止删除当前登录账号」保护） |
| 当前登录账号识别 | 平台能力 | 现有 useAuth / AppAuthGuard 注入的 req.appUser |

**所需 API**:
```typescript
// 删除系统账号，物理删除；保护：内置管理员 400、删除自身 400、不存在 404 [领域模型: AppUser] [对应页面功能: 删除账号]
DELETE /api/auth/users/:id
Response: { success: boolean }
```
