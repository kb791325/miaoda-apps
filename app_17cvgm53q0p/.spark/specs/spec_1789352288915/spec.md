# 需求分析

## 用户故事

1. 飞书一键登录：点击「飞书登录」直接绑定当前飞书账号并进入系统
  - 1.1 当前飞书账号已绑定系统账号时，点击「飞书登录」直接进入系统首页
  - 1.2 未绑定但按手机号/姓名能唯一匹配到一个启用中的系统账号时，自动完成绑定并直接登录，提示「已自动绑定当前飞书账号」
  - 1.3 自动匹配未命中时进入账号密码绑定页，绑定成功后直接登录
  - 1.4 登录过程中按钮有加载态，失败时在页面内展示错误原因
2. 账号密码绑定支持覆盖绑定，解除历史绑定死锁
  - 2.1 系统账号已绑定其他飞书账号时，输入正确密码可覆盖旧绑定并登录（以密码为准恢复绑定权）
  - 2.2 当前飞书账号已绑定其他系统账号时，验证密码成功后绑定改绑到新账号并登录
  - 2.3 密码错误或账号禁用时绑定失败并展示原因
3. 登录页首次访问不再误报「登录已过期」
  - 3.1 本次会话从未登录成功过（仅本地残留过期 token）时，进入登录页不弹出「登录已过期」提示
  - 3.2 使用中登录态真实过期被退回登录页时，保留过期提示

## 页面列表

### 登录页
1. 「飞书登录」按钮点击后触发一键登录，过程展示加载态
2. 自动绑定成功时提示「已自动绑定当前飞书账号」并跳转首页
3. 自动匹配未命中时切换账号密码绑定表单，顶部说明首次使用需绑定
4. 绑定表单提交支持覆盖绑定场景，错误原因在表单内展示

# 技术方案

## 开发元信息
- 开发模式: 全栈应用
- 涉及层级: 服务端, 前端（复用现有 app_user 表与飞书绑定字段，不新增表、不新增插件）

## 业务模型

### API 设计

#### 登录页 相关
**页面路径**: /login
**功能全景**：
| 功能 | 实现方式 | 说明 |
|------|----------|------|
| 飞书一键登录（已绑定直接登录） | API | POST /api/auth/feishu-login，沿用 req.userContext.userId 匹配 app_user.feishu_user_id |
| 未绑定时自动匹配绑定 | API + 平台能力 | 服务端经平台通讯录服务（AuthNPaasService，使用平台内置服务：user-identity）获取当前飞书用户的手机号/姓名，与 app_user 匹配后写绑定 |
| 账号密码绑定（覆盖绑定） | API | POST /api/auth/feishu-bind，密码验证通过后允许覆盖两侧旧绑定 |
| 会话校验与隐式会话兜底 | 平台能力 | 现有 AppAuthGuard 飞书身份兜底逻辑保持不变 |
| 过期提示去误报 | 前端 | AuthProvider 的 401 事件处理仅在本会话曾登录成功时弹 toast |

**所需 API**:

```typescript
// 飞书一键登录：已绑定直接登录；未绑定时按手机号→姓名顺序唯一匹配启用账号并自动绑定；未命中返回 409 FEISHU_UNBOUND [领域模型: AppUserModel] [对应页面功能: 1、2、3]
POST /api/auth/feishu-login
Response: {
  token: string;
  user: AppUserWithRole;
  permissions: string[];
  autoBound?: boolean; // 本次请求触发了自动绑定，前端据此提示「已自动绑定当前飞书账号」
}

// 账号密码绑定：密码验证成功后覆盖绑定（系统账号已绑其他飞书账号→覆盖；飞书账号已绑其他系统账号→改绑） [领域模型: AppUserModel] [对应页面功能: 3、4]
POST /api/auth/feishu-bind
Body: { username: string; password: string }
Response: 同 feishu-login
```

**服务端改造要点**：
- `AuthService.feishuLogin`：未命中绑定时，通过平台通讯录服务读取当前飞书用户资料（手机号优先、姓名兜底），仅当唯一命中一个启用中且未绑定飞书的系统账号时写入 `feishu_user_id` 并签发会话（`autoBound: true`）；通讯录服务不可用或匹配不唯一时保持返回 409 FEISHU_UNBOUND，走绑定表单兜底；自动绑定写入复用唯一索引冲突（23505）处理
- `AuthService.feishuBind`：保留密码校验与账号状态校验；删除「该系统账号已绑定其他飞书账号」「该飞书账号已绑定其他系统账号」两处 409 拦截，改为验证密码通过后直接覆盖写入绑定（先把占用同一飞书 ID 的旧账号解绑，再写入新绑定，唯一索引冲突兜底提示）

**前端改造要点**：
- 登录页：`feishuLogin` 成功且 `autoBound` 为真时 toast「已自动绑定当前飞书账号」；未命中进入绑定模式的说明文案保持现状
- `use-auth` AuthProvider：401 事件处理器仅在「本会话曾存在有效用户态」时弹「登录已过期」toast，首次带着过期 token 进入登录页静默清理
