# 需求分析

## 用户故事

1. 验证登录与首页工作台
  - 1.1 使用管理员账号可成功登录并进入首页工作台
  - 1.2 工作台按角色权限渲染快捷卡片、待办列表与数据总览区块
  - 1.3 存在逾期应收时展示逾期提醒卡片（逾期金额与笔数），点击可跳转应收列表逾期视图
2. 验证新增订单与自动联动
  - 2.1 新增订单弹窗选择客户与商品后保存成功，订单出现在列表并高亮该行
  - 2.2 订单金额等于商品金额加向客户收取费用合计
  - 2.3 系统自动生成该订单对应的应收记录，到期日默认加 30 天
  - 2.4 取消订单后状态变为已取消，对应应收变为已作废
3. 验证配送安装状态流转
  - 3.1 对待出库配送单在确认出库对话框填写配送信息后提交，状态变为运输中
  - 3.2 出库后对应商品库存减少，生成发货出库库存流水
  - 3.3 开始安装并完成安装（填写安装费用与验收信息）后，配送单变为已完成，订单状态同步为已完成
4. 验证商品与库存
  - 4.1 手动表单新增商品（名称/销售单价/初始库存）成功，SKU 自动生成
  - 4.2 商品列表可为商品设置成本价，毛利率随售价与成本计算展示
  - 4.3 盘点操作（必填备注）成功，生成盘点调整库存流水且库存按差额变化
  - 4.4 库存预警视图按库存升序展示并高亮预警商品
5. 验证客户与跟进记录
  - 5.1 查看客户档案，负责销售与信用额度信息正常展示
  - 5.2 新增跟进记录成功，列表按客户分组展示且该记录可见
6. 验证应收收款
  - 6.1 应收列表展示逾期天数徽标与汇总数据
  - 6.2 登记收款后未收金额减少，部分收款显示部分结清、收满显示已结清
  - 6.3 收款金额超过未收余额时被阻断并提示
7. 验证应付与付款
  - 7.1 创建应付（选择供应商与金额）保存成功
  - 7.2 登记付款后未付金额减少，状态正确流转
8. 验证费用审批与资金流水
  - 8.1 新建费用成功，状态为待审批
  - 8.2 审批通过后状态变为已审批，自动生成费用支出资金流水
  - 8.3 驳回后状态变为已驳回，仅待审批状态的费用可编辑删除
9. 验证对账单生成
  - 9.1 对账预览可汇总账期内往来与收付款数据
  - 9.2 生成对账单成功，可在对账列表与详情中查看
10. 验证系统管理页面
  - 10.1 用户管理页正常展示用户列表（含账号类型标识）
  - 10.2 角色权限页正常展示角色列表与权限配置
11. 验证库存流水台账
  - 11.1 流水页分页展示库存流水，含变动前后库存与操作人
  - 11.2 按业务类型筛选返回对应结果

# 技术方案

## 开发元信息
- 开发模式: 全栈应用（本次为既有功能验收测试，不新增代码）
- 涉及层级: [前端, 服务端]（验收对象为已实现的前后端功能）

## 验收测试策略

### 测试方式
- 采用浏览器实际操作测试（standard 模式），以用户视角点击、填写、提交，走完业务流程
- 断言落到应用内可观察的终态结果（状态变化、列表新增/消失、徽标与汇总更新）与接口响应，不停留在"弹窗打开/按钮存在"等中间态

### 轮次安排
- 最多 3 轮，每轮不超过 5 个用例
- 第 1 轮覆盖核心主链路：订单→配送→安装、财务收付款与费用审批、主数据与工作台
- 第 2、3 轮仅定向复测上一轮失败与未完成的用例；已通过的用例不重复测试

### 副作用限制
- 不测试跟进提醒发送（会真实发送飞书消息）
- 不测试商品图片识别新增（沙箱文件上传链路受限）
- 对账单分享链接仅验证应用内生成与详情查看，不验证外部免登录访问

### 测试数据要求
- 带副作用的创建/删除操作遵循"验证后还原"原则：取消测试订单、删除测试商品/费用/供应商等，避免污染既有业务数据
- 配送出库会真实扣减库存，优先选择库存充足的测试商品，验收后记录变动以便追溯

### 阻塞处理
- 入口页不可用（白屏 / Page not found）时停止全部验收，优先排查服务编译与运行状态，恢复后再继续
- 同一用例未经修复连续失败 2 次即停止复测，转为根因分析并记录问题
