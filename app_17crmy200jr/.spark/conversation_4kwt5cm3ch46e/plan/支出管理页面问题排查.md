## 目标与成功标准

排查支出管理页面（`/expenses`）在 E2E 验收中暴露的两个问题：
1. 页面 reload 后偶发白屏（Cases 3-5 失败）
2. 首轮 E2E 中表格无数据行（API 有 745 条但表格未渲染）

## 关键实现文件

- `client/src/pages/Expenses/ExpensesPage.tsx` — 主页面，含数据加载、状态管理、轮询逻辑
- `client/src/pages/Expenses/ExpenseTable.tsx` — 表格组件，数据渲染入口
- `client/src/api/expenses.ts` — API 调用层
- `client/src/app.tsx:26` — 路由注册

## 实现方案

派遣 Reviewer 对 ExpensesPage 及其子组件进行代码审查，聚焦：
1. **白屏根因**：检查组件的 error boundary、数据加载失败时的兜底渲染、状态初始化逻辑
2. **表格数据不渲染**：检查数据加载链路（API → state → table props），排查是否有条件渲染导致数据到位后表格未更新
3. **路由稳定性**：确认路由配置没有冲突

## 具体步骤

1. 加载 `reviewer-usage` skill
2. 派遣 Reviewer 审查 `client/src/pages/Expenses/` 下所有文件，重点关注状态管理与数据渲染链路
3. 根据 Reviewer 返回的问题清单，制定修复方案

## 影响范围与风险

- 支出管理页面是核心功能页面，修改需谨慎
- 白屏问题可能影响所有依赖该页面的用户

## 验收标准

- Reviewer 返回的问题清单中，每个问题都有明确的根因分析和修复建议
- 白屏问题定位到具体代码行
- 表格数据不渲染问题定位到具体原因
