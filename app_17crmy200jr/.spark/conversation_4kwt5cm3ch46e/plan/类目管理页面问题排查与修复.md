## 目标与成功标准

排查类目管理页面（`/categories`）的潜在问题并修复，确保数据展示完整、操作响应正确。

## 关键实现文件

- `client/src/pages/Categories/CategoriesPage.tsx:134-188` — 数据加载逻辑，含 L1/L2 加载和 useEffect 联动
- `client/src/pages/Categories/CategoriesPage.tsx:231-260` — L1 提交处理，含冗余的 loadL2List 调用
- `client/src/api/categories.ts:16-27` — L2 列表 API 调用，未传 pageSize
- `server/modules/categories/categories.service.ts:46-90` — L2 后端默认 pageSize=50，上限 100

## 已识别问题

### 问题 1：L2 列表可能截断（严重度：中）
- 现象：L2 后端默认 `pageSize=50`，前端未传 `pageSize`，若某 L1 下有 >50 个 L2 类目，超出部分不显示
- 修复：前端 `getCategoriesL2` 调用时传入 `pageSize: 200`（与 FixedAssets 类目加载一致）

### 问题 2：L1 编辑后 L2 重复加载（严重度：低）
- 现象：`handleSubmitL1` 中 `setSelectedL1Name(name)` 触发 useEffect 自动调用 `loadL2List(name)`，随后又手动调用一次
- 修复：删除 `handleSubmitL1` 中的手动 `loadL2List` 调用（第 251-253 行），依赖 useEffect 自动刷新

### 问题 3：L2 列表无总数提示（严重度：低）
- 现象：若 L2 数量较多，用户无法判断是否已展示全部数据
- 修复：利用后端返回的 `total` 字段，在 L2 表格上方显示总数

## 具体步骤

1. 修改 `client/src/api/categories.ts`：`getCategoriesL2` 调用时传入 `pageSize: 200`
2. 修改 `client/src/pages/Categories/CategoriesPage.tsx`：
   - 删除 `handleSubmitL1` 中第 251-253 行的手动 `loadL2List` 调用
   - 在 L2 表格区域标题旁显示当前数量/总数

## 影响范围

- 不影响 L1 列表的增删改查
- 不影响 L2 的增删改功能
- L2 分页参数调整仅影响展示数量，不影响其他页面调用 `getCategoriesL2`

## 验收标准

- 创建 51+ 个 L2 类目后，全部可见
- 编辑 L1 名称后，L2 列表刷新一次（非两次）
- L2 列表区域显示数量信息
