# 凭据轮换指南

## 1. 凭据清单

| 凭据名称 | 用途 | 存储位置 | 轮换周期 | 影响范围 |
|---------|------|---------|---------|---------|
| DATABASE_URL | 数据库连接 | 环境变量 | 90天 | 全部服务 |
| JWT_SECRET | JWT签名 | 环境变量 | 60天 | 用户会话失效 |
| JWT_REFRESH_SECRET | 刷新令牌签名 | 环境变量 | 60天 | 刷新令牌失效 |
| SESSION_SECRET | 会话加密 | 环境变量 | 30天 | 用户会话失效 |
| COOKIE_SECRET | Cookie签名 | 环境变量 | 30天 | Cookie失效 |
| FEISHU_APP_SECRET | 飞书API认证 | 环境变量/飞书后台 | 90天 | 飞书集成 |
| REDIS_PASSWORD | Redis认证 | 环境变量 | 90天 | 缓存服务 |

## 2. 轮换流程

### 飞书 APP_SECRET 轮换

1. 登录飞书开放平台 → 应用管理 → 凭证与基础信息
2. 点击"重置"生成新的 App Secret
3. 更新环境变量 `FEISHU_APP_SECRET`
4. 重启应用服务
5. 验证飞书API调用正常

### 数据库密码轮换

1. 在数据库执行 `ALTER USER` 修改密码
2. 更新 `DATABASE_URL` 环境变量
3. 重启应用服务
4. 验证数据库连接和数据查询正常

### JWT_SECRET 轮换

1. 使用 `npx tsx scripts/generate-secret.ts -l 64` 生成新密钥
2. 更新 `JWT_SECRET` 环境变量
3. 注意：轮换后所有现有 JWT 令牌立即失效，用户需重新登录
4. 建议在低峰期执行
5. 重启应用服务

### SESSION_SECRET / COOKIE_SECRET 轮换

1. 使用 `npx tsx scripts/generate-secret.ts -l 32` 生成新密钥
2. 更新对应环境变量
3. 轮换后所有现有会话和 Cookie 失效
4. 重启应用服务

## 3. 轮换检查清单

- [ ] 已通知相关团队轮换计划
- [ ] 已选择低峰时段
- [ ] 已备份当前凭据（安全存储）
- [ ] 已生成新凭据
- [ ] 已更新环境变量
- [ ] 已重启应用
- [ ] 已验证核心功能正常
- [ ] 已确认旧凭据已失效

## 4. 应急回滚

### 轮换失败回滚

1. 恢复之前的凭据值到环境变量
2. 重启应用
3. 验证服务恢复
4. 分析失败原因后重新规划

### 凭据泄露应急处理

1. 立即轮换泄露的凭据
2. 检查访问日志，评估泄露影响范围
3. 强制所有用户重新登录（如泄露的是 JWT/SESSION 凭据）
4. 记录事件并上报安全团队
5. 审查泄露原因，修复安全漏洞

## 5. 安全最佳实践

- 密码最小长度 32 字符，包含大小写字母、数字和特殊字符
- 使用 `crypto.randomBytes(64).toString('hex')` 生成密钥
- 凭据仅通过环境变量注入，禁止硬编码或配置文件存储
- 生产环境凭据与开发/测试环境完全隔离
- 定期审计凭据访问日志
- 限制凭据的访问权限（最小权限原则）
