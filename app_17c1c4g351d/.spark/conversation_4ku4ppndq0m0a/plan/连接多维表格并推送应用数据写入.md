- 应用连接多维表格「电商售后客服智能处理与数据复盘系统」（appToken: TtUqb0FwVaSq7ssq6vacWbMCn9c），用户在设置页可将应用数据**写入**该多维表格

- 成功标准：点击「推送到多维表格」后多维表格中出现与应用一致的数据，重复点击不新增重复行

## 具体步骤
1. **核查插件实例绑定**：对现有 6 个实例逐一 `get_plugin_ai_json`（已知 `feishu_bitable_product_sync_reader_1` 绑定客户咨询表），按 outputSchema 字段名识别各自绑定的表；为售后工单表/商品库存表/数据复盘表各确定一个实例，用 `plugin_instance` UPDATE 增加 `batchAddRecords`、`batchUpdateRecords` 动作（实例已具备则跳过），无绑定实例则 CREATE 新实例；记录最终实例 ID 写入服务端常量表 `BITABLE_WRITER_IDS`
2. **拉全字段列表**：`lark-cli base +field-list` 不截断地获取 3 张表完整字段，修正上方映射中的字段名（如安全库存/可用库存）
3. **类型与后端**：先改 `shared/api.interface.ts` 类型，再在 service 实现 `pushToBitable`：
   - 幂等策略：售后工单表按工单编号、商品库存表按 SKU编码 先 `searchRecords` 取已有值集合，仅批量新增缺失记录（`batchAddRecords` ≤500）；数据复盘表按统计日期查当日记录，存在则 `batchUpdateRecords`、不存在则新增
   - controller 增加推送端点；从 `req.userContext` 取 userId 仅用于日志
4. **前端**：`data-import.ts` 加推送函数；`BitableSyncSection` 的 3 个实体卡片增加「推送到多维表格」按钮（上传云图标，推送中禁用+旋转），结果用 toast + 现有 Badge 状态样式展示；仅实体已有配置时可用（与现有同步按钮条件一致）
5. **预填连接配置**：通过现有 `POST api/data-import/bitable-config` 为 3 个实体写入配置（appToken=TtUqb0FwVaSq7ssq6vacWbMCn9c、各自 tableId、label），设置页显示「已连接」
6. **验证**：接口自测 3 个实体的推送（验证 pushed/skipped 计数），重复推送第二次应全部 skipped；服务端日志无错

## 影响范围与风险
- 不改动现有「多维表格→应用」同步逻辑；仅新增写入链路
- 插件实例 UPDATE 若被平台重新生成实例，需以 `get_plugin_ai_json` 返回的最终 ID 为准更新服务端常量
- 数据复盘表的差评数/负面情绪数在应用内无数据源，固定写 0（公式字段退款率/差评率由表内公式自动计算）

## 验收标准
- 设置页 3 个实体显示已连接，各出现「推送到多维表格」按钮
- 推送售后工单后，多维表格售后工单表新增记录与应用售后数据一致，状态为合法选项值
- 推送库存后，商品库存表记录数与应用一致，库存状态公式列自动显示「预警/正常」
- 推送复盘后，数据复盘表出现当日汇总行；再次推送同日不新增、仅更新
- 重复推送售后/库存返回 skipped=已有条数、pushed=0，表格无重复行
- 接口返回 2xx，服务端日志无错误
