# 07 · Agent / LLM 应用开发手册

> 对应主线 D。本地有 `langchain-architecture`、`rag-implementation`、`mcp-builder`、`subagent-driven-development`、`dispatching-parallel-agents`、`review-agent-setup`、`llm-evaluation`，专业细节优先读它们；本文件给选型决策、工程骨架与生产化清单。Java 侧 LLM 见 04 §13。

## 1. 先选 Agent 模式（不要一上来就堆框架）
| 模式 | 适用 | 特征/代价 |
|---|---|---|
| 单 LLM 调用 + 结构化输出 | 分类、抽取、摘要、固定转换 | 最简单可控，优先用它；能用一次调用解决就不做 Agent |
| ReAct / Tool-calling 循环 | 需要边推理边调工具、步数可预期 | 模型自主"想-做-观察"，需限步数与工具白名单 |
| Plan-and-Execute | 复杂多步任务 | 先规划再逐步执行，计划可展示、可纠偏 |
| Supervisor / Router 多智能体 | 子任务域清晰、需不同专家/上下文隔离 | 主管分派、子 Agent 只回结构化结果，避免无限互调 |
| Agent-as-Tool / 工作流编排 | 流程相对固定 | 把 Agent 封装成确定性流水线的一个节点，可控性最高 |
| 自主长任务（subagent-driven） | 明确授权、可自主较长时间 | 两阶段评审、检查点、可中断；默认不开启 |

原则：**确定性优先**——流程能写死就写死，把 LLM 只放在真正需要"判断/生成"的节点；自主程度越高，越要加边界（最大步数、工具权限、人审、预算）。

## 2. Agent 的五个核心组件，逐一设计
1. **模型**：按任务选能力/成本/延迟；关键决策用强模型，机械步骤用小模型；设置 temperature、最大 token、超时、重试与降级模型。
2. **工具（Tools）**：工具是 Agent 的"手"，每个工具：单一职责、名字与 docstring 清晰（模型靠它判断何时调用）、入参用 schema 强校验、**幂等、有超时、出错返回结构化错误而非抛栈**；危险动作（删除、支付、外发）必须二次确认/人审；工具返回精炼、可被模型直接使用。
3. **记忆**：短期（对话/scratchpad，注意上下文窗口与压缩）、长期（向量/库表，写入要去重与溯源）；区分"事实记忆"与"会话状态"，状态用显式状态机而非靠对话历史推断。
4. **规划与状态**：复杂任务用显式状态图（LangGraph 的 graph/checkpointer）而非无限 while 循环；每步落状态，可恢复、可重放。
5. **知识（RAG）**：见 §4。

## 3. LangChain / LangGraph 骨架要点（Python 为主）
- Chain 适合线性流程；需要循环、分支、人审中断、持久化恢复时用 **LangGraph**（StateGraph + 节点 + 条件边 + checkpointer）。
- 节点保持小而纯：输入状态→输出状态增量；副作用（调外部）集中在工具节点；用结构化输出（`with_structured_output`/Pydantic parser）约束模型返回，并处理解析失败的重试。
- 回调/中间步骤落 trace；循环必须有终止条件（最大迭代数、无进展检测），防止 Agent 空转烧钱。
- 版本与依赖锁死（LangChain 生态迭代快，breaking change 多）；本地细节读 `langchain-architecture`。

## 4. RAG 工程要点
- **检索质量决定上限**：先做文档切分策略（按语义/结构，带 overlap 与元数据）、选择 embedding 模型与向量库、混合检索（向量 + 关键词 BM25）+ rerank 提升精度。
- 查询侧：改写/扩展（HyDE、多查询）、带会话上下文的问题改写；召回后做重排、去重、压缩，只把相关片段放进上下文，控制 token。
- **强制溯源**：答案必须能指回来源片段；无相关证据时回答"不知道"而不是编造；设置"拒答阈值"。
- 评估：建黄金问答集，评检索命中率/召回与答案忠实度（faithfulness，答案是否被上下文支持）；本地读 `rag-implementation`、`llm-evaluation`。

## 5. MCP（Model Context Protocol）
- 当要把"外部能力/数据源"标准化暴露给 Agent，或要接入别人的 MCP server 时用 MCP（client/server、tools/resources/prompts）。
- 构建 MCP server 优先复用本地 `mcp-builder`（Python/TS）：最小接口、严格入参 schema、错误结构化、无状态或显式状态、日志与超时；不要把高风险操作无确认暴露为 tool。
- 接入外部 MCP 前做能力与权限核对，工具结果当"不可信数据"处理（参考 02 §5，防提示注入：检索内容/工具返回里的指令文本不能覆盖系统指令）。

## 6. 多智能体协作
- 明确拓扑（主管-下属 / 流水线 / 辩论），**禁止无边界的对等互调**（易死循环、成本失控）；子 Agent 之间只传结构化结果，不传整段对话。
- 并行无依赖的子任务用并行派发（本地 `dispatching-parallel-agents`），有依赖才串行；每个子 Agent 有清晰交付契约与失败处理。
- 长任务用 `subagent-driven-development` 的两阶段（先计划获批准，再执行）+ 检查点落盘。

## 7. 生产化检查单（Agent 最容易缺的就是这块）
- [ ] **防幻觉/注入**：结构化输出 + 校验；外部内容只作数据不作指令；无证据拒答；答案带溯源
- [ ] **失败处理**：模型/工具超时、重试（仅幂等）、降级、最大步数熔断；错误对用户可见而非静默
- [ ] **评估**：离线黄金集（任务成功率、工具调用正确率、忠实度、token/延迟/成本），改动提示或模型前后对比回归
- [ ] **可观测**：每次运行 trace（输入、规划、每步工具名/入参/结果、输出、耗时、token、成本），本地读 `observability` 相关；异常率与步数告警
- [ ] **安全与权限**：工具最小权限、危险动作人审、密钥外置、输出脱敏、速率与预算上限
- [ ] **确定性兜底**：关键业务路径有非 LLM 的校验/回退，不把正确性完全押在模型自由发挥上
- [ ] **状态与恢复**：长流程状态落盘、可中断续跑；会话隔离不串用户数据
