## 实现方案

### 一、前端请求层修复（关键）
**文件：`client/src/api/request.ts`**
- BASE_URL 改为同源相对路径 `/api`（Vite 代理转发到后端），移除端口直连逻辑
- 所有 fetch 请求自动注入 CSRF header：从 cookie 读 `suda-csrf-token`，放到 `x-suda-csrf-token` header
- credentials 设为 `same-origin`（同源代理场景）
- mock 降级保留但降低触发权重：仅 HTTP 5xx + 连续 3 次失败才降级，避免 404/403 误触发

**文件：`vite.config.ts`**
- 新增 server.proxy：`/api` → `http://localhost:3000`，`/app/app_17czx1jrsqe` 路径重写去掉前缀（或直接代理到 `http://localhost:3000/app/app_17czx1jrsqe`）
- 新增 server.proxy：`/app/app_17czx1jrsqe` → `http://localhost:3000`（透传路径，保证 CSRF cookie 同源）

### 二、后端常驻与端口确认
- 确认 `nest start --watch` 进程常驻 3000 端口，已由 dev.js 管理（MAX_RESTART_COUNT 机制）
- 修改 `SERVER_PORT` 环境变量到与前端一致（3000，与现有一致，无需改）

### 三、全表测试残留清理
通过服务端 BitableService 遍历 32 张表：
- 关键词：「测试」「test」「CRUD」「映射」「权限」「前端映射」「联调」
- 逐表列出删除条数与剩余条数
- 只删名称/编号字段命中的记录，不误删正常业务模拟数据
- 涉及表：公海客资、无效客资、线索、联系人、跟进记录、开户申请、报备、转户、提成（广告）、财务 18 张表（客户明细/收款/充值/退款/消耗/垫款/发票/端口/银行/成本/收入/支出/退币/后返/扣减/激励/费用管理/保证金押金）

### 四、四态防崩验证
- **真实数据**：接口 200 返回正常数据 → 正常渲染
- **mock 兜底**：手动关闭后端 → 自动降级到 mock，显示「后端服务暂时不可用」toast
- **接口报错**：接口返回 5xx → 显示错误提示 + 重试按钮，不白屏
- **返回空**：接口返回空数组 → 显示空状态组件，不崩溃
- 重点检查：所有 `.toFixed()`、`.map()`、深层属性访问都有 `?.` / `?? []` / `|| 0` 兜底
- 验证页面：工作台 + 客户管理 + 开户申请 + 消耗管理 + 收款管理
