
# 提成规则抽屉修复方案

## 一、取证结论

### 1. 数据线根因（两个）

**根因 A：`res.data` 是包装对象，裸数组**
- 实测接口 `GET /api/entity/业务-提成规则/list
- 返回结构：`{ code:0, data:{ list:[...], total, page, page_size, has_more, next_page_token }`
- 代码：`commissionRulesApi.all()` → `_commissionRulesApi.list()`，entity-factory 第191-193行 返回 `data:{...res.data, list}` 包装
- 旧代码 `(res.data as Rule[]) || []` 把包装对象强转为数组，`rules.find()` 渲染期抛 `TypeError: rules.find is not a function`，整棵组件树崩溃，白屏 / 渲染中断导致 loading 永远 true**根因 B：`tiers` 字段是 JSON 字符串，渲染期 `.map/.filter` 继续抛错**
- `client/src/api/index.ts 第661行 `calculate` 方法：`try { tiers = JSON.parse(rule.tiers || '[]'); } catch { tiers = []; }` ——证明 Bitable 中 `阶梯配置` 列是 text/longtext 文本存的 JSON 串
- 抽屉 `selectRule`（106行）、`handleSave`（202行）、渲染（382行）、`calcCommission`（165行）都直接把 `rule.tiers` 当数组用
- 即使 `rules` 归一化成数组，每条的 `tiers` 仍是字符串，`.map/.filter/.sort` 继续在渲染期抛错

### 2. 布局线根因

**根因：抽屉内容宽度不足 + 档位 grid 列固定列数且标签长度撑破**
- DrawerContent 写死 `max-w-[720px]`（268行）
- 左侧规则列表固定 `w-56`（224px）固定宽度（275行）
- 右侧可用约 496px，档位区 `grid-cols-3` 三列平分，每列约 140px 左右，Label「起比例（含）」等 6 字标签放不下→文字换行或截断；`
-档位行是 flex 容器 `min-width:0` 约束，input 撑破容器宽度溢出，底部出现横向滚动条
- 公共 Drawer `w-3/4 sm:max-w-sm` 默认更窄，本组件用 `max-w-[720px]` 覆盖了但 720px 仍不够

## 二、改动清单（仅 1 个文件）

**文件：`client/src/components/CommissionRuleDrawer.tsx**

## 三、数据线修复

### 3.1 数组归一化函数（局部，与 VideoCommissionPage 内 `asRuleList` 口径一致，不抽公共函数）
- 新增局部函数 `asRuleList(value: unknown): Rule[]`，口径：Array直用，对象取 list/records/data，其余返 []
- `loadRules` 中 `res.data` 归一化后再 `setRules`
- 每条规则的 `tiers` 字段统一 `JSON.parse` 成 `Tier[]`，失败返空数组

### 3.2 loading 闭合保证
- `loadRules` 保留 try/catch/finally 已有 finally 里 `setLoading(false)`（已有）
- 新增 `loadError` 状态，请求失败时显示「加载失败，点击重试」按钮，按钮调用 `loadRules()`

### 3.3 三种终态
- 加载中 → 显示"加载中..."
- 空数组 → 显示「暂无提成规则，点击新增」（带新增按钮
- 失败 → 显示错误提示 + 重试按钮

### 3.4 `tiers` 字符串转数组（所有读写全链路修复
- 读取：归一化时对每条规则的 `tiers` 做 parse，string→数组
- 写入：保存时 `tiers: JSON.stringify(validTiers.map(...))` 转回字符串（与 create/update 兼容 Bitable text 列）
- `handleDelete` 中 `rules` 引用的 `filter` 后的 `remaining[0]` 已是数组型 tiers，安全
- `calcCommission` 入参 `rule.tiers` 已是数组，安全

## 四、布局线修复

### 4.1 抽屉宽度调大
- `DrawerContent` `max-w-[900px]` → `max-w-[960px]`（960px，足够放下左列表 240px + 右侧 720px）
- 小屏自适应：保留 `w-full` + `max-w-[960px]` 不变

### 4.2 档位区布局优化
- 档位行：`grid-cols-3` → `grid-cols-3` 不变，加 `min-w-0` 约束每列
- Label 文字：`起（≥）` / 止（不含）` / `比例（%）` 缩短文字保持不变，但加 `whitespace-nowrap` + 防止换行
- 档位整体 flex 容器加 `min-w-0`，防止 input 不溢出
- 「快速试算」区块宽度自适应

### 4.3 内部滚动
- 内容区 `overflow-y-auto` 已存在保留，横向滚动条只在内部出现

## 五、具体步骤

1. **数据线**：

## 六、影响范围与风险

- **影响范围**：仅 `CommissionRuleDrawer.tsx` 一个文件
- **不触碰**：后端接口、全局 Drawer 公共组件、广告业务模块、「重新计算」链路、提成列表其他按钮逻辑
- **回归风险**：tiers 写入时 JSON.stringify 与 calculate 方法一致，读 parse 前后端已有先例
- **兼容性**：空 tiers 数据：字符串型存
  - 旧数据 tiers 是字符串，parse 后正常渲染
  - 新数据保存时 stringify，与旧格式一致
- **「重新计算」不受影响**：VideoCommissionPage 内的 asRuleList 不动，calculate 方法不动

## 七、验收标准

1. 点「提成规则」抽屉完整展开，无横向滚动条，档位标签完整显示不截断
2. 规则列表正常渲染已有规则（如有），loading 能正常结束
3. 四种数据场景：
   - 正常返回数组 → 列表渲染
   - 空数组 → 空状态提示 + 新增按钮
   - 包装对象 → 正确解包
   - 接口报错 → 错误提示 + 重试按钮
4. 抽屉内功能：新增规则、编辑、添加档位、适用部门开关、快速试算均可用
5. 「重新计算」功能正常（VideoCommissionPage 逻辑未动
6. tsc 类型检查通过，devServer 无报错
