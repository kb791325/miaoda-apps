- ✅ 页面齐全：11 个一级模块、数十个列表/详情页，界面完整可用

### 后端（NestJS）

- ❌ 之前的 Express + Bitable 业务后端（server/index.ts + routes/ + services/ + middleware/ + utils/ + config/）已被删除
- ❌ 上一次发布失败根因：`better-sqlite3` 需要 native 编译（node-gyp + make），CI 环境无 make，导致 npm install 失败

### 数据源

- ✅ 配置：`APP_ID=cli_aa1e4a98577a1cbb`、`BASE_TOKEN=FzAKbTGyFaGvWUstz52cZimQnOb`
- ✅ 工作台聚合数据验证有效：昨日消耗 517,532.62、本月消耗 3,301,648.05、本月新开单 24

## 核心策略

**用 NestJS 原生模块直接对接飞书 Bitable，彻底移除 SQLite / better-sqlite3 依赖。**

理由：
1. 业务数据全部在飞书多维表，SQLite 仅用于用户表+系统设置，可由内存 Map + 飞书用户体系替代
2. 去掉 better-sqlite3 即可解决发布时的编译失败
3. 符合平台 NestJS + Drizzle 全栈模板规范

## 实施步骤

### Phase 1：后端基础设施
- 移除 `better-sqlite3` 依赖（npm uninstall）
- 创建 `server/config/feishu.config.ts`：飞书 App ID / App Secret / Base Token 从环境变量读取
- 创建 `server/common/feishu/bitable.service.ts`：
  - tenant_access_token 缓存 + 自动刷新 + 失效重试
  - records CRUD（list/search/get/create/update/delete/batchDelete）
  - 通用错误处理 + 429 退避
- 创建 `server/common/feishu/field-normalizer.service.ts`：字段值归一化（单选/多选/人员/日期/数字/超链接/附件/关联表）

### Phase 2：Bitable 实体 CRUD 模块
- 创建 `server/modules/bitable/bitable.module.ts` + `bitable.controller.ts` + `bitable.service.ts`
- 表配置：32 张逻辑表名 → table_id 映射、keyword 搜索字段、权限字段、敏感字段
- 接口（全部 `/api/entity/:tableKey`）：
  - `GET` 列表（page/pageSize/keyword/sortBy/sortOrder/filter/dateRange）
  - `GET /:recordId` 详情
  - `POST` 新增
  - `PUT /:recordId` 更新
  - `DELETE /:recordId` 删除
  - `POST /batch-delete` 批量删除
- 权限：从请求头 `x-user-name` / `x-user-role` 解析，管理层看全部、经理按部门、销售按本人
- 字段脱敏：销售角色隐藏敏感字段（金额等）
- 注册到 `app.module.ts`（ViewModule 之前）

### Phase 3：工作台聚合模块
- 创建 `server/modules/dashboard/dashboard.module.ts` + `dashboard.controller.ts` + `dashboard.service.ts`
- 接口（全部 `/api/dashboard/`）：
  - `GET /summary?range=today|week|month|year` — 5 个指标卡数据
  - `GET /realtime` — 今日实时消耗（内/外/集团）
  - `GET /charts?time_dim=today|week|month|year` — 5 个图表数据
  - `GET /rankings?port=all|inner|outer&time_dim=week|month|year` — 5 个排行
  - `GET /targets` — 目标详情
  - `GET /performance` — 绩效任务
- 聚合逻辑：从「财务-消耗」「财务-充值」「客户管理」「广告-开户申请」表现实计算
- 返回 snake_case 字段，前端 dashboard-api.ts 已做映射

### Phase 4：质量保障与四态防崩溃
- 后端全局异常过滤器（已有 GlobalExceptionFilter），所有 Bitable 调用 try/catch 包装返回 `{code: 500, message}`
- 前端已有的 mock 降级保留（2 次失败自动切换）
- 前端 ErrorBoundary + Skeleton + 空状态 + toast 错误提示已具备
- 后端加 `/api/health` 健康检查端点

### Phase 5：构建与正式发布

- `npm run typecheck` 通过

  - 客户管理、广告开户、财务消耗等列表显示真实数据
  - mock 降级在接口异常时仍可用
