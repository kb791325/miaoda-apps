## 目标与成功标准
- 用户访问 `/` 时正常渲染工作台页面，不再空白
- 角色权限导航不出现重定向循环

## 根因
`client/src/app.tsx:23` 的 `<Route index element={<HomeRedirect />}>` 优先级高于同层级 `<Route path="/" element={<WorkbenchPage />}>`，访问 `/` 始终走 `HomeRedirect`；而 `shared/roles.ts` 中 `PAGE_ROLE_MAP` 第一项就是 `'/'`，`HomeRedirect` 找到首个有权限路径后 `<Navigate to="/" replace />` 跳回 `/`，形成死循环，页面空白。

## 关键实现文件
- `client/src/app.tsx` — 调整 index 路由指向，消除重定向循环
- `client/src/components/HomeRedirect.tsx` — 兜底：跳过首页路径自身，防止未来再出现同类循环
- `shared/roles.ts` — 确认 `PAGE_ROLE_MAP` 第一项不再导致循环

## 实现方案
### 1. 路由层修复（主修复）
将 `app.tsx` 中 `WorkbenchPage` 的路由改为 index 路由，删除独立的 `<Route index element={<HomeRedirect />}>`：
- 原：`<Route index element={<HomeRedirect />} />` + `<Route path="/" element={<WorkbenchPage />} />`
- 改：`<Route index element={<WorkbenchPage />} />`（删除独立的 index 重定向路由；保留 `path="/"` 的写法也行，但必须保证 `WorkbenchPage` 是 index 路由且 `HomeRedirect` 不作为 `/` 的 index）

### 2. HomeRedirect 兜底加固（防回归）
`HomeRedirect.tsx` 中遍历 `PAGE_ROLE_MAP` 找首个有权限路径时，跳过 `'/'`（或与当前路径相同的路径），从第二个有效路径开始找，避免未来把 `/` 放回第一位时再次自循环。

### 3. 导航菜单一致性校验
确认左侧导航的「工作台」菜单项 `to="/"` 与路由一致，`NavLink` 能正确高亮。

## 具体步骤
1. 读 `client/src/app.tsx`，确认当前路由结构
2. 删除 `<Route index element={<HomeRedirect />} />`，将 `WorkbenchPage` 路由改为 `index`（保留 `path="workbench"` 可选，看现有结构）
3. 读 `client/src/components/HomeRedirect.tsx`，在循环中加过滤：跳过路径为 `'/'` 的项
4. 读 `shared/roles.ts`，确认 `PAGE_ROLE_MAP` 结构无需改动（跳过逻辑已兜底）
5. 浏览器访问 `/` 验证工作台渲染，访问无权限路径验证 HomeRedirect 仍能跳到首个有权限页

## 影响范围与风险
- 影响：首页渲染、未授权页跳转逻辑
- 风险：HomeRedirect 跳过 `/` 后，若用户只对首页有权限、对其他页都无权限，会找不到跳转目标 → 需兜底：找不到其他有权限页时跳到 `/`（正常落地），不构成循环
