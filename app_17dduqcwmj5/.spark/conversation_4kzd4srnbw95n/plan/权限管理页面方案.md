## 目标与成功标准
- 校长/管理员可在应用内新页面 `/permissions`（权限管理）查看 4 个角色及其成员，为角色分配/移除用户、部门、群组成员，并可增删改角色
- 成功标准：校长进入页面看到角色表格（含成员胶囊摘要）；通过「编辑成员」选人保存后 `+role-match-list` 能查到新成员；非校长角色看不到该菜单且访问路由跳 /unauthorized

## 关键实现文件
- `server/modules/role-manager/role-manager.controller.ts`（新建）：透传 AuthorizationSDK，`@Controller('api/role_manager')`，类级 `@NeedLogin()` + `@CanRole([APP_ROLES.principal])`
- `server/modules/role-manager/role-manager.module.ts`（新建）：注册 controller；在 `server/app.module.ts` imports 中 ViewModule 之前加入
- `shared/api.interface.ts`（追加）：re-export SDK 类型（ForceRoleDTO/RoleMemberDTO/MemberMutationData/UserSimpleDTO/DepartmentDTO/ChatSimpleDTO/PresetGroupDTO 等）+ 请求类型（CreateRoleRequest/UpdateRoleRequest/AddMembersRequest/RemoveMembersRequest）；写入前先读该文件确认无命名冲突
- `client/src/api/index.ts`（追加）：getRoles/getRole/createRole/updateRole/deleteRole/listRoleMembers/addRoleMembers/removeRoleMembers/clearRoleMembers，axiosForBackend，每个函数在 response 层检查 `status === 403` 抛错（403 不进 catch）
- `client/src/pages/permissions/`（新建 4 文件）：`PermissionsPage.tsx`（表格+编排，≤500行）、`MemberSummary.tsx`（成员胶囊列）、`EditMembersDialog.tsx`（编辑成员弹窗）、`RoleFormDialog.tsx`（新建/编辑角色弹窗）
- `shared/roles.ts`：`PAGE_ROLE_MAP['/permissions'] = [APP_ROLES.principal]`
- `client/src/app.tsx`：加 `permissions` 路由，ProtectedRoute requiredRoles 取 PAGE_ROLE_MAP
- `client/src/components/Layout.tsx`：NAV_ITEMS 加 `{ path: '/permissions', label: '权限管理', icon: ShieldCheck }`（CanRole 经 PAGE_ROLE_MAP 自动只向校长展示）

## 实现方案
### 后端（静态角色 + 运行态角色管理，AuthorizationSDK）
- controller 照抄 authz-guide runtime-role-controller-spec 模板（不含 search 端点，前端选人组件自带搜索）：角色 list/get/create/update/delete + 成员 list/add/batch_remove/clear
- 注入 `AuthorizationSDK`（AuthZPaasModule 全局注册，直接 constructor 注入）；不写 try-catch，SDK 统一转 HttpException

### 前端页面（严格对标 management-page-spec）
- 表格用 `@lark-apaas/client-toolkit/antd-table`，五列：角色名称(180)/描述(300，空显--)/标识(200)/成员摘要(250)/操作(150)
- 成员摘要：特殊范围用 ItemPill（企业全员 Building/互联网公开 Globe/应用开发者 Users，品牌色圆底）；指定成员用 UserSelectTag/DepartmentSelectTag/ChatSelectTag（disabled + `!opacity-100 !cursor-default`，禁用 UserDisplay）；超 3 个显 `+N` Badge + HoverCard（禁 Tooltip/Popover）
- 编辑成员弹窗：区块一特殊范围（应用开发者可切换 Switch，企业全员/互联网公开仅包含时展示且 disabled）；区块二指定成员三子区块直接复用 business-ui 的 UserSelect/DepartmentSelect/ChatSelect（button 模式）；保存=全量替换（clear 后一次 add 合并提交：`userList:[{userID}]`、`departmentList:[{id}]`、`groupChatList:[{chatID}]`、`isContainsAdmin`）
- 操作列：外露「编辑成员」文字按钮；更多菜单含「编辑角色信息」「删除角色」（含 allEmployees/public 时 disabled 且 Tooltip 提示原因）；删除用 AlertDialog 二次确认
- 刷新列表不设 loading（防闪烁），错误统一 toast

5. 接口自测（GET roles；创建 `[API_TEST]` 角色→get→update→delete 闭环；成员接口在测试角色上验证后随角色删除）
6. 提交；登录态页面效果由您本人浏览器验证（E2E 沙箱为游客会话无法进入校长页面）

## 影响范围与风险
- 仅校长可访问页面与接口，其他角色 403/菜单不可见，不影响现有功能
- 角色删除是真实平台操作：误删在用角色会导致对应页面不可访问，删除前有二次确认
- 编辑成员采用清空重建，保存瞬间角色成员短暂为空（平台标准做法）

## 验收标准
- GET `/api/role_manager/roles` 返回 4 个角色且含 roleMembers；匿名/非校长调用受限
- 页面表格五列渲染正确，成员胶囊样式符合规格（光标非禁止态）
- 编辑成员弹窗三选择器可用，保存后列表成员即时更新
- `[API_TEST]` 角色创建/改名/删除闭环成功且无残留
- 非校长用户（如学员角色）访问 /permissions 跳 /unauthorized，侧边栏无该菜单项
