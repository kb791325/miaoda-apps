# 课程删除功能方案

## 目标与成功标准
- 校长可在课程列表删除课程；课程存在任何关联数据（排期、报名学员、配方、工艺流程、器材工具、营销内容、素材库关联）时禁止删除并提示具体原因；删除成功后列表即时刷新
- 非校长角色：接口 403，且前端不显示删除按钮

## 关键实现文件
- `server/modules/course/course.service.ts` — 新增 `deleteCourse(courseId)`，复用 `getCourseRow`、`courseLinkCondition`、`bitableSyncService.deleteRecord`（参照 `course.service.ts:216` deleteCategory 与 `:482` deleteEquipment 模式）
- `server/modules/course/course.controller.ts` — 新增 `@Delete(':id')` 路由，`@CanRole([APP_ROLES.principal])`，放在所有静态路由（categories/equipments/process-flows/formulas）之后（参照 `:92` deleteCategory 写法，返回 `{ id }`）
- `client/src/pages/courses/course.api.ts` — 新增 `deleteCourse(id)`，DELETE `/api/courses/${id}`
- `client/src/pages/courses/CourseCard.tsx` — 新增可选 `onDelete?: (id: string) => void` prop 与删除按钮（参照现有 `onEdit` 按钮 `CourseCard.tsx:78` 写法，Trash2 图标 ghost 样式）
- `client/src/pages/courses/CourseListPage.tsx` — 接入删除确认弹窗（`components/ui/alert-dialog.tsx`）、调用 API、sonner 提示、刷新列表；仅校长角色传入 `onDelete`（复用项目内现有角色判断方式，与 Layout 菜单角色过滤同源）

## 实现方案

### 后端删除逻辑（block_any_related）
1. `getCourseRow(courseId)` 校验课程存在（不存在抛 `NotFoundException`）
2. 用 `db.select({ count }).from(...).where(...)` 逐项统计关联数量，jsonb 关联表统一走 `courseLinkCondition(col, course)`（含 uuid 与 baseRecordId 双匹配）：
   - `courseScheduleTable.courseName`（排期）
   - `studentRegistrationTable.enrollCourse`（报名学员）
   - `formulaDetailTable.courseRelated`（配方）
   - `processFlowTable.course`（工艺流程）
   - `equipmentToolTable.courseAffiliation`（器材工具）
   - `contentMaterialLibrary.relatedCourse`（素材库）
   - `marketingContent.courseId` 直接 `eq(course.id)`（营销内容）
3. 任一计数 > 0 → `ConflictException`，消息列出存在的关联类型，如「该课程仍有排期、报名学员，请先清理后再删除」
4. 全部为 0 → 先 `bitableSyncService.deleteRecord('course', courseId)`，再 `db.delete(...).where(eq(id)).returning({ id })` 校验生效行数（为空抛 `NotFoundException`），logger 记录删除

### 前端交互
1. `CourseCard` 删除按钮放在编辑按钮旁（同一操作区），点击 `event.stopPropagation()` 后调 `onDelete(item.id)`
2. `CourseListPage` 维护待删除课程状态，`AlertDialog` 展示课程名 + 警示文案「删除后不可恢复」，确认后调 `deleteCourse`：成功 → sonner 成功提示 + 重新拉取当前页列表；409 → 展示后端返回的冲突原因；其他错误 → sonner 错误提示
3. 权限收敛：仅当前用户命中 `APP_ROLES.principal` 时向 `CourseCard` 传入 `onDelete`（先 grep 项目现有角色判断用法并复用，不新造轮子）

## 具体步骤
1. 后端：`course.service.ts` 加 `deleteCourse`（含 7 项关联计数检查 + 多维表格同步删除）→ `course.controller.ts` 加 `@Delete(':id')`（仅 principal）→ 编译通过
2. 前端：`course.api.ts` 加 `deleteCourse` → `CourseCard` 加删除按钮 → `CourseListPage` 加确认弹窗与刷新逻辑 → 校长角色门控
3. 接口自测（@CanRole 端点 api_request 恒 403，须用 bash curl 自拼 `x-larkgw-suda-webuser`（含 roles 数组，urlencode）+ CSRF 头）：
   - 创建 `[API_TEST]` 课程 → DELETE → 200 且 GET detail 404
   - 对有排期/学员的课程执行 DELETE → 409 且消息含关联类型
   - 不存在 id → 404；webuser 不带 principal 角色 → 403
4. 读运行时日志确认无错误，提交代码

## 影响范围与风险
- `@Delete(':id')` 与现有 `DELETE categories/:id` 等两段路径不冲突（段数不同）
- 多维表格同步删除若失败沿用现有 `deleteRecord` 的错误处理语义，与 deleteCategory 一致
- 不改共享类型（复用 `CourseWriteResponse` 形态 `{ id }`），无 schema 变更

## 验收标准
- 校长删除无关联课程：弹窗确认 → 成功提示 → 列表移除该课程，多维表格记录同步删除
- 删除有排期或学员的课程：收到 409 冲突提示并指明关联类型，数据未被删除
- 招生老师/授课老师：接口 403，页面不显示删除按钮
- 编辑/详情等现有功能不受影响，路由无冲突
