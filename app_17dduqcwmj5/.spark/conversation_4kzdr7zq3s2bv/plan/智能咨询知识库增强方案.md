# 智能咨询知识库增强方案

## 1. 目标与成功标准
- 用户提问后，无论知识库是否精确命中，都能得到一段基于知识库内容、自然流畅的 AI 答复，不再出现「无法回答」式的敷衍回复
- 命中时：基于匹配到的标准答案 + 相近 FAQ 上下文，由 AI 润色生成更人性化的回答
- 未命中时：选取 TOP 3 最相关的 FAQ 作为上下文，AI 基于知识库现有内容给出尽量有帮助的引导性答复，同时问题仍记入待补充列表
- 回复末尾展示「参考来源」，透明告知用户答案依据

## 2. 关键实现文件

| 文件 | 改动内容 |
|------|----------|
| `server/modules/consultation/consultation.service.ts` | 重构 `matchFaq` 主流程：新增 TOP N 召回、相似度排序、统一 AI 答复生成；未命中不再直接返回 fallback |
| `server/modules/consultation/consultation.controller.ts` | 响应结构兼容（已有字段够用，新增 `relatedFaqs` 可选字段） |
| `shared/consultation.ts` | `FaqMatchResponse` 新增 `relatedFaqs?: FaqListItem[]` 字段 |
| `client/src/pages/consultation/ConsultationChatPanel.tsx` | 支持展示「参考来源」多条；未命中时不再显示兜底话术，展示 AI 生成的引导回复 |
| `client/src/pages/consultation/consultation.api.ts` | 类型同步（已从 shared 导入，无需改动逻辑） |

## 3. 实现方案

### 3.1 后端：召回 TOP N 相关 FAQ（替代当前单条精确匹配）

- 在 `matchFaq` 中，先查全量启用的 FAQ（已有），然后计算相似度排序，取 TOP 3
- 相似度算法（分层策略，按优先级）：
  1. **意图识别匹配**（已有 `recognizeByIntent`）：命中的排第 1，置信度最高
  2. **关键词命中数**：问题与 FAQ 关键词交集越多得分越高
  3. **文本相似度**：用 Jaccard 相似度（基于分词/字符级 bigram）计算问题与 FAQ 标题+相似问的相似度
- 返回 TOP 3 相关 FAQ，不再只返回 1 条

### 3.2 后端：统一 AI 答复生成（命中 / 未命中共用同一通道）

- 去掉「未命中 → 返回 fallback」的分支，所有情况都调 AI 生成答复
- 传给答复生成插件的 `search_results` 从 1 条扩展为 TOP 3 相关 FAQ 的完整信息（问题 + 答案 + 分类）
- 新增 system prompt 引导（拼在 query 前或作为独立字段，视插件 input schema 决定）：
  - 明确告知 AI：你是餐饮培训机构的智能客服，必须基于下方知识库内容回答
  - 禁止回答「无法回答」「我不知道」之类的敷衍话术
  - 如果知识库内容不能直接回答，要基于最相关的内容做引导，推荐用户查看相关课程/联系招生老师
- 命中（TOP 1 高置信度）：AI 以第 1 条标准答案为主润色回答
- 未命中（TOP 1 相似度低于阈值）：AI 综合 TOP 3 给出引导式回复，问题仍写入 `faq_miss` 表

### 3.3 后端：相似度阈值与分级

- 设两级阈值：
  - `HIGH_SIM_THRESHOLD`：高于此值视为「精确命中」，`matched=true`，以第 1 条为主答
  - 低于此值视为「相关推荐」，`matched=false`，但仍返回 AI 生成的引导回复
- 阈值取字符级 bigram Jaccard 相似度 0.3 作为初值（可后续调优）

### 3.4 前端：展示优化

- 参考来源展示从「单条」改为「多条列表」（最多 3 条），格式：`参考：1. xxx  2. yyy`
- 未命中时不再显示「该问题已记入待补充」的生硬文案，改为 AI 自然回复末尾加一句淡灰色提示：「以上回答基于知识库相关内容整理，如需更准确的信息可联系招生老师」
- loading 文案优化：从「AI 正在识别问题并生成答复」改为更短的「正在思考...」

## 4. 具体步骤

1. **后端 service 重构 `matchFaq`**
   - 新增 `computeSimilarityScore(question, faqRow)` 方法：关键词命中数 + bigram Jaccard 综合打分
   - 新增 `rankFaqs(question, rows)` 方法：返回按分数降序的 TOP 3
   - 改写 `matchFaq` 主流程：查全量 → 排序取 TOP 3 → 调 AI 生成 → 返回统一结构
   - 未命中仍写 `faq_miss` 表（保留待补充运营能力）

2. **后端 `generateAnswer` 升级**
   - 参数从单条 `row` 改为 `topFaqs: FaqRow[]`
   - `search_results` 传 TOP 3 每条的「问题+分类+标准答案」
   - 新增引导语（拼在 query 前）：明确角色、回答规则、禁止敷衍

3. **类型同步**
   - `shared/consultation.ts` 的 `FaqMatchResponse` 加 `relatedFaqs?: FaqListItem[]`
   - controller 返回值适配

4. **前端对话面板适配**
   - `ChatMessage.reference` 改为多条或直接用 `relatedFaqs` 渲染
   - 未命中场景的文案调整
   - 参考来源样式优化（序号列表）

## 5. 影响范围与风险

- **影响范围**：仅智能咨询模块，不影响知识库管理、待补充列表等其他功能
- **风险点**：
  - AI 答复生成耗时可能增加（TOP 3 上下文更长），但在可接受范围（2-3s）
  - 未命中场景 AI 可能编造信息 → 通过 prompt 强约束「只能基于知识库内容回答」+ 末尾标注「AI 生成仅供参考」降低风险
  - 插件 schema 可能不支持自定义 system prompt → 降级为把引导语拼在 query 前面

## 6. 验收标准

- [ ] 问「多少钱」→ 命中「学费是多少？可以分期吗？」，回复内容包含具体学费/分期相关信息，不再出现「无法回答」
- [ ] 问一个知识库完全没有的问题（如「你们学校地址在哪」）→ 返回 AI 基于最相关 FAQ 生成的引导回复，末尾有参考来源，且问题出现在待补充列表
- [ ] 参考来源展示多条相关 FAQ（命中时至少 1 条，未命中时 1-3 条）
- [ ] 接口响应时间 < 5s（AI 生成时间）
- [ ] 知识库管理、待补充列表等其他功能不受影响

## 7. 未决事项

- 答复生成插件 `knowledge_base_answer_generation_1` 的 input schema 是否支持 system prompt / 角色设定？若不支持，用 query 前缀引导语方案兜底
- 相似度阈值初始值需根据实际 FAQ 数据调优，初版取 0.3，后续可根据运营数据调整
