# 清理未跟踪文件解决发布提示方案

## 目标与成功标准
- 消除发布前"当前有任务代码未提交"提示的根因困扰
- 明确 11 个未跟踪（U）文件的性质与正确处理方式
- 不破坏平台插件运行、不丢失工作区记忆

## 关键事实核查结论

### 10 个 `server/capabilities/*_writeback_1.json` 文件
- 性质：平台插件实例投影文件，属于**受保护目录**，agent 禁止删除/修改
- 引用状态：代码中未被直接引用（通过 plugin_instance id 动态加载，不走文件路径 import）
- 已跟踪的同类文件有 17 个（如 `bitable_attendance_sync_2.json`、`faq_knowledge_base_writeback_2.json` 等），这 10 个是新增未入库的插件实例投影
- 发布影响：**不进入构建产物**，发布由平台侧实例配置兜底，本地 capabilities 目录仅为 dev 环境投影
- 结论：**不能删，也不需要删**

### 1 个 `.agent-memory/topics/auth-env-boundaries.md` 文件
- 性质：工作区记忆系统的主题文件，从 MEMORY.md 中"鉴权环境边界"条目链接引用
- 用途：保存 dev 环境 @NeedLogin 不返回 401、E2E 游客会话等跨会话复用的排查经验
- 发布影响：`.agent-memory/` 由平台排除，不进入发布
- 结论：**有用，不建议删**；删了会丢失跨会话记忆，但不影响应用运行

## 实现方案

### 正确处理方式：直接点"继续发布"
- 这些未跟踪文件全部是平台生成目录（capabilities 投影 + agent 记忆），**不属于应用业务代码**
- 发布检查的"未提交"提示是 git 层面的通用提醒，不代表这些文件会影响发布
- 点"继续发布"即可正常发布，功能不受影响

### 备选：若坚持清理视觉噪声
- `.gitignore` 为平台敏感配置，**禁止修改**（已验证：修改会被 forbidden）
- `skip-worktree` 仅对已跟踪文件有效，对未跟踪（??）文件无效
- 实际可行路径：**忽略即可**，U 条目不影响发布、不影响功能

### 关于 capabilities 文件为何是未跟踪状态
- 已跟踪的 17 个 capabilities 是早期版本随代码提交的
- 这 10 个 `_writeback_1` 是后续通过 plugin_instance 工具创建的新实例，平台投影到本地但未自动 git add
- 它们与已跟踪的 `*_sync_2`、`*_writeback_2` 性质相同，都是运行时插件配置

## 影响范围与风险
- 删除 capabilities 文件 → 本地 dev 环境对应插件实例加载失败，功能报错
- 删除 .agent-memory/topics → 丢失跨会话排查经验记忆，下次遇到同类问题需重新排查
- 两者都不会影响线上发布产物（发布不依赖本地 capabilities 文件和 memory 文件）

## 验收标准
- 确认 10 个 capabilities 文件确属受保护目录、不可由 agent 删除
- 确认 1 个 memory 文件被 MEMORY.md 链接引用、有实际用途
- 确认"继续发布"路径可用，这些文件不进入构建产物
